# Contributing

Thanks for helping with Synapse.

## Workflow
1. Pick or open an issue and comment that you are working on it.
2. Create a branch from `main`: `feature/short-name` or `fix/short-name`.
3. Make small, focused commits with clear messages.
4. Open a pull request. Describe what changed and how you tested it.
5. At least one other person reviews before merging.

## Rules
- Do not commit real student data, credentials or API keys.
- Answers must come from approved content, with a source. Do not invent policy.
- Keep sensitive topics (appeals, hardship, wellbeing, legal) routed to staff.
- Keep the interface accessible: keyboard use, readable contrast, 44px tap targets.

## Content changes
FAQ entries live in the `KB` list in `index.html`. Each entry needs a topic, question, keywords, answer and source. Ask the content owner to approve changes before merging.
